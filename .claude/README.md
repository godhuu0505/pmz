# Claude Code ハーネス（AI駆動開発の足場）

このディレクトリは、本リポジトリで **Claude Code による AI 駆動開発を効果的に回す** ための
ハーネス（足場）です。要件定義（`docs/requirements.md`）で確定した MVP を、
仕様駆動・要件トレーサブルに実装していくことを狙います。

## 構成

| 要素 | パス | 役割 |
|------|------|------|
| プロジェクトメモリ | `../CLAUDE.md` | 全セッション冒頭で読む共有コンテキスト（MVPスコープ・設計インバリアント・コマンド・規約） |
| 設定 / 権限 | `settings.json` | 権限の allow/ask/deny と SessionStart フック登録（チーム共有） |
| 起動フック | `hooks/session-start.sh` | Web セッション開始時に `uv sync` で依存導入し `.venv` を PATH に載せる（同期・冪等） |
| サブエージェント | `agents/*.md` | 文脈隔離した専門ワーカー（受け入れ基準抽出 / 合成データ作成） |
| スラッシュコマンド | `commands/*.md` | 定型ワークフロー（`/trace` = PR→要件トレース） |
| 要件ヒアリング | `skills/grill-me/SKILL.md` | 新規論点を実装前に詰めるための既存スキル |

## 適用したベストプラクティス（ハーネスエンジニアリング）

1. **再現性のある環境ブートストラップ** — SessionStart フックで依存を自動導入。
   Web セッションでも tests/linters が即座に走り、エージェントが「ツールが無い」で詰まらない。
   コンテナ状態はフック完了後にキャッシュされるため `uv sync` を採用（冪等・非対話）。
2. **持続コンテキストの外部化** — 暗黙知を `CLAUDE.md` に集約。MVPスコープ・**設計インバリアント**
   （プロンプトインジェクション隔離・3値＋棄権・ハードガード等）・コマンド・規約を毎回ロードし、
   セッション間で判断がブレないようにする。
3. **タイトなフィードバックループ** — 「変更したら必ず `ruff check` と `pytest` を green に」を
   CLAUDE.md で規約化し、実コード（`src/pmz`＋`tests`）を最初から lint/test green で用意。
4. **最小権限** — `settings.json` で開発に必要な範囲だけ allow、`git push` は ask、破壊的操作と
   secrets 読取は deny。エージェントの自律性を保ちつつ事故の上限を固定する。
5. **文脈隔離した専門サブエージェント** — 大量のファイル読みや専門判断はサブエージェントに委譲し、
   メインの文脈を汚さない。記述（description）を具体的にして適切に自動委譲させる。
6. **仕様駆動 / 要件トレーサビリティ** — 実装・データ・コマンドを要件 §番号や要件IDに紐づける。
   これは pmz 自身の差別化（PM観点＝要件充足判定）と同じ規律をコードベースにも適用したもの。

## 拡張のしかた

- Phase2/3 に進むときは、新しいサブエージェント（例: 振り返り/ルール進化、評価セット回帰テスト）や
  `/eval` のようなコマンドを足す。判断が要る新論点は先に `grill-me` で詰める。
- 起動を速くしたい場合、`hooks/session-start.sh` を async 化できる（依存導入完了前に
  エージェントが走り出すレースには注意）。

## 個人設定

`settings.local.json` と `CLAUDE.local.md` は `.gitignore` 済み（個人の上書き用、共有しない）。
