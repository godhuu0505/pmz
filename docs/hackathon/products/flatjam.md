## ② 社会課題

- **作曲という創造行為のハードル**: 「自分には無理だと思っていた作曲が、手軽に作れた」という
  ユーザー声に象徴されるとおり、作曲初心者は **どこから手をつけるか／どんな技法があるか分からず行き詰まる**【確認済み】。
- **技法・知識の発見困難**: コード進行・スケール・メロディ技法などの「先人の知恵」は
  **文化的背景とセットで散在**しており、初心者が自分の表現意図に合うものへ到達しにくい【確認済み】。
- **音楽教育における個別最適化の欠如**: 学校の音楽教育で、生徒一人ひとりの感性・創造性を
  個別に伸ばす（personalized education）のは人手では困難【確認済み】。
- **「AI全自動生成」では創造性が育たない**という問題意識: プロンプトを入れて AI が丸ごと曲を生成する
  方式は、人間の **吟味・選択・自己表現の機会を奪い**、教育的に逆効果という立場を取る【確認済み】。
- ターゲット: **音楽教育の指導者と生徒**、および作曲初心者・行き詰まったクリエイター【確認済み】。

## ③ 解決内容（主要機能）

中核思想は **「AIが曲を作るのではなく、人間が作るのを助ける」**。創造性の解放には
「**自分の手で試す → 感性で吟味する → 選択する**」プロセスが最重要、という設計哲学【確認済み】。

主要機能:
1. **リアルタイム作曲プロセス解析**: ユーザーの創作文脈（何を表現したいか）をリアルタイムに解析【確認済み】。
2. **「セレンディピティ」提示**: 「セレンディピティ」を **文化的背景とともに体系化された作曲知識・技法**と定義し、
   ユーザーの表現意図の文脈に合わせて **候補として提示**する。AIが選んで生成するのではなく
   人間が吟味・選択する【確認済み】。
   - 提示される技法の例: **コード進行**（王道進行・カノン進行など実曲で使われるもの）、
     **メロディ技法**（ペンタトニックスケール、メロディの反復など）、
     **ジャンル/楽器/雰囲気を指定する生成プロンプト**【確認済み】。
   - **各技法を代表曲（実例）に紐づけ**て提示し、**音楽の専門家がファクトチェック**して
     全データの正確性を担保【確認済み】。
3. **作曲UI（Composition UI）**: ユーザーが実際に手を動かして作曲する画面【確度中】。
4. **AIエージェントとの対話**: 学習者がエージェントと対話しながら作曲し、
   **自分の感性に音楽的なラベルを付ける**経験を通して、作曲を自己表現の手段として認識する【確認済み】。
- 効果（ユーザー声）: 「無理だと思っていた作曲が手軽にできた」「インスピレーションや感性に合う提案を試すと、
  そのまま自分のスタイルで続けられた」【確認済み】。

## ⑤ 技術的工夫ポイント

1. **「全自動生成」を意図的に避けたエージェント設計**: Gemini に曲を作らせるのではなく、
   **表現意図の文脈解析 → 適切な技法候補の検索・提示**にエージェントの役割を限定。
   人間の選択を中心に据えた「co-pilot」型【確認済み】。
2. **知識ベースの信頼性担保**: 技法データを **音楽専門家がファクトチェック**し、各技法を **代表曲に紐づけ**。
   LLM のハルシネーションを「人手検証済みの構造化データ」で抑える設計【確認済み】。
   → pmz の「正本（canonical）」「客観シグナルのみで判定」思想と同型。
3. **リアルタイム文脈解析**: 作曲プロセスを止めずに、進行中の創作文脈を解析して
   その場で技法候補を出す（レイテンシ/インタラクティブ性の作り込み）【確認済み】。
4. **「セレンディピティ」というレコメンド設計**: 単なる類似推薦ではなく、
   **文化的背景込みの技法を意図に沿って差し出す**ことで「偶然の良い出会い」を演出。
   レコメンドを *教育的体験* に昇華した点が新規性【確認済み】。

## ⑧ pmz への学び

pmz = AIリリースゲートキーパー。FlatJam（最優秀賞）から流用できる戦術:

1. **「AIに全部やらせない」を旗印にする** 【最重要】:
   FlatJam の勝ち筋は「全自動生成への反命題＝人間の吟味・選択を中心に据える」。
   pmz も「**AIが勝手にマージしない／棄権を許す／人間にエスカレーション**」（条件付き自律・3値判定）を
   **弱点ではなく思想的差別化**として前面に出すべき。「自信満々の誤判定をしない門番」を旗印に。

2. **知識ベースの人手検証＝信頼性の演出**:
   FlatJam は技法データを **専門家がファクトチェック**して信頼性を訴求。
   pmz の「**正本（canonical acceptance criteria）は人間確定**」「客観シグナルのみで判定」は同型の強みなので、
   デモで「この承認根拠は人手確定の正本＋CI緑＋ハードガード由来」と**監査証跡を見せて信頼性を演出**する。

3. **before/after の物語＋情緒曲線**:
   FlatJam は「無理→できた」の感情曲線で共感を作った。
   pmz は §9.1 のアーク「**見逃して障害 → 学習 → 同型を検知ブロック**」を
   **before/after 混同行列＋時系列グラフ**で「賢くなる様子」を見せる設計。これが審査の山場。
   FlatJam の教訓: 指標だけでなく **"悔しい見逃し→救済" の物語**として演出すると刺さる。

4. **短尺デモで「触る→提案→選ぶ→結果」を一周見せる**:
   3分で価値の一周を見せる。pmz も「PR来る→ゲートが解析→根拠コメント→Go/No-Go→（再発型を）ブロック」を
   **1本のPRストーリー**で完走させる。だらだら機能列挙せず一本道で。

5. **ドメインの「伝わりやすさ」ハンデの自覚と対策**:
   音楽は即・直感的に伝わるが、**リリース判定は地味**。
   FlatJam に勝てない土俵で戦わず、pmz は「**障害を未然に止めた / PM観点で要件未達を見抜いた**」という
   **危機回避のドラマ性**（オンコールの悪夢→回避）で情緒を作る必要がある。

6. **審査3軸への明示的マッピング**:
   FlatJam は ①アイデアの質 ②課題と解決の有効性 ③実現度 を全部押さえた。
   pmz も提出記事で **3軸に逐一対応**させる（新規性=PM観点リリース判定、課題=属人的Go/No-Go、
   実現度=Cloud Run+Gemini+ADK+Terraform の実働）。

7. **思想を一言のキャッチに圧縮**:
   FlatJam =「創造性を奪わず育てる」。pmz も「**Pre-Merge Zero（誤承認ゼロを目指す門番）**」など
   §1.1 のバックロニムを **ピッチの一言フック**に使う。
